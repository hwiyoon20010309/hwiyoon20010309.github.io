## 개요

TeachING은 링크 하나만으로 학습 자료를 자동 수집·분석하여, 나만의 학습 로드맵으로 정리해주는 AI 학습 서비스입니다. 흩어져 있는 정보를 연결해 하나의 지식 체계로 만드는 것을 목표로 합니다.

## 문제 · 해결 · 성과

* **문제** : 학습에 필요한 정보가 여러 링크와 플랫폼에 흩어져 있어 스스로 정리하고 체계화하기 어려웠고, 자료를 모아도 요약·분류를 해두지 않으면 나중에 다시 찾아보기 힘들었습니다. 또한 RDB와 Vector DB 간 데이터 정합성이 깨지거나, 관련 자료가 있는데도 RAG 챗봇이 임계값 문제로 답을 찾지 못하는 등 신뢰도 문제도 있었습니다.
* **해결** : URL 하나만 입력하면 자료를 자동 수집·크롤링하고, AI가 핵심 요약(3~5줄)과 시맨틱 태그를 생성해 자동으로 분류하도록 설계했습니다. Qdrant 벡터DB 기반 RAG 챗봇 파이프라인을 구축해 자료 기반 질의응답을 제공하고, top-K 튜닝·Multiquery·citation 표기로 검색 정확도를 개선했습니다. Qdrant 동기화 시점을 DB 커밋 이후로 옮기고 검색 임계값을 실측 기준으로 재조정해 데이터 정합성과 답변 신뢰도를 확보했습니다.
* **성과** : 흩어진 자료를 자동 요약·분류해 나만의 학습 로드맵(티칭맵)으로 정리할 수 있게 됐습니다. RDB-VectorDB 정합성 이슈, RAG 검색 실패, 배포 연쇄 장애 등 실서비스 수준의 안정성 문제를 계층별로 하나씩 해결해 안정적인 운영 환경을 확보했고, 챗봇 사용량 제한과 동시성 문제까지 해결해 실제 트래픽 상황에서도 안정적으로 서비스할 수 있습니다.

## Service Flow

1. **URL Input** — URL 링크 하나만으로 학습 자료 자동 수집 및 크롤링 시작
2. **AI Analysis** — 자료를 핵심 요약(3~5줄)과 의미론적 분석을 통한 시맨틱 태그 생성
3. **Categorization** — 기존 보관함 데이터와 비교하여 폴더 위치 제안 및 자동 분류 정리
4. **Interactive Tech** — 핵심 문장 하이라이트와 클릭 시 나타나는 AI 과외 선생님의 맞춤형 보충 해설

## 주요 페이지

* 메인페이지, 보관함 페이지(폴더별 자료 정리), 티칭맵 페이지(학습 로드맵), AI 챗봇 페이지

## What I did

* **챗봇(RAG) 파이프라인** : Qdrant 벡터DB 연동 및 RAG 파이프라인 설계/구현, 검색 정확도 개선(top-K 상향, 대표 청크 제한 제거, 본문 키워드 직접 매칭 단계 추가, Multiquery 기능), 답변 출처(citation) 표기 개선, 챗봇 무료 요금제 사용량 제한 구현(대화방 10개/일일 질문 5회) 및 동시 요청 시 레이스 컨디션 수정, 안정성 버그 다수 수정(고아 청크로 인한 500 에러, OpenAI 임베딩 배치 실패 문제를 100개 단위 분할 처리로 해결)
* **자료(Material) AI 분석** : AI 자료 분석 생성 파이프라인 구현(프롬프트 빌더, 응답 파서, OpenAI 연동), 자료 재분석(forceAnalyze) 시 동시성 가드 추가 및 중복 생성 이슈 해결, 자료 상세 조회 API 정리 및 AI 상세 분석 수정 기능 추가, URL/Notion 등 원문 수집 → 분석용 텍스트 추출 파이프라인 공동 개발(Notion/Selenium 렌더링 안정화, 보호된 소스 감지, URL 이미지 분석 파이프라인 구현)

## Troubleshooting & Lesson Learned

* **RDB - Vector DB 정합성 이슈** — URL 분석 파이프라인에서 RDB 트랜잭션이 끝나기 전 Qdrant를 먼저 동기화해, RDB 롤백 시 Qdrant만 변경값이 남아 데이터가 불일치하는 현상 발생. Qdrant payload 동기화를 `@TransactionalEventListener(AFTER_COMMIT)`로 이전해 DB 커밋이 성공한 시점에만 외부 저장소를 갱신하도록 설계해 해결. *커밋 이후로 동기화 시점을 옮기는 것만으로 데이터 불일치 위험을 제거할 수 있었다.*
* **RAG 챗봇 검색 실패** — 관련 자료가 실제로 존재함에도 챗봇이 검색 임계값에 걸려 "참고할 자료 없음"으로 오답을 반환. 검색 임계값을 실측 점수 기준으로 완화(0.75 → 0.3)하고, 엔티티 컬럼을 MEDIUMTEXT로 명시, position 누락 시 fallback 값 부여로 저장 실패까지 차단. *RAG 품질은 임베딩 모델보다 임계값 같은 파라미터 튜닝이 체감 성능을 크게 좌우한다.*
* **RDB - 자료 복구 동시성 제어** — '복구 가능 여부 사전 체크'와 '복구 UPDATE 실행'이 분리되어 있어 동시 요청 시 일관성이 깨질 위험 존재. 비관적 락 대신 체크 조건을 UPDATE 쿼리의 WHERE 절에 직접 포함시켜 원자적으로 처리, 영향받은 row가 0이면 예외를 던지도록 구조화. *락 없이도 쿼리 설계만으로 레이스 컨디션을 제거할 수 있으며, 성능 저하 없는 동시성 제어가 가능하다.*
* **EC2 최초 배포 연쇄 장애** — YAML 문법 오류, deprecated 이미지, 디스크·메모리 부족, .env 인코딩 문제 등이 연쇄적으로 발생해 배포가 반복 실패. 최신 이미지 교체, 스토리지 볼륨 확장, swap 메모리 추가, dos2unix 인코딩 변환을 통해 계층별(이미지 → 리소스 → 인코딩)로 하나씩 순차 해결. *배포 장애 시 계층별로 하나씩 분리해 접근하면 순차적으로 해결할 수 있다.*
